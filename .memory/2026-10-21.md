# 2026-10-21

## 代码审查（Go 后端 + Vue 前端）

全量静态审查：`go vet ./...` 通过、`go test -race ./internal/...` 通过（依赖需 `GOPROXY=https://goproxy.cn,direct`，proxy.golang.org 在本机不通）。

确认的问题：
1. **致命**：`main.go` `OnBeforeClose` 在 `MinimizeToTray=true`（默认值）时返回 true；Wails darwin 的 `Frontend.Quit()` 因 prevent=true 跳过 `mainWindow.Quit()`，而 `quitAppFn` 已先执行 `tray.Quit()` → 进程变僵尸（无窗口无托盘）。
2. **高**：`internal/tunnel/tunnel.go` `connect()` 用 `ssh.NewClientConn` 未设 deadline（`ssh.ClientConfig.Timeout` 只对 `ssh.Dial` 生效），对端只 accept 不发 banner 时握手永久阻塞 → `Stop()` 永不返回。已写临时测试复现（5s 超时失败）。
3. **中**：`pipe()` 只等一个方向就返回且不传播半关闭 → 半关闭协议数据截断/挂死。已复现。
4. **中**：keepalive 用 `SendRequest(wantReply=true)` 无超时，链路静默死亡时永久阻塞，起不到探测作用。
5. **中**：Vue `TunnelEdit.vue` 依赖 `onMounted` 读 `route.params.id`，同一路由记录内 /edit/:id → /edit 复用组件，表单残留旧 ID，保存会覆盖旧隧道。
6. 其他：`dock.Hide/Show` 在 goroutine 里调 AppKit；`Store.persist` 并发写文件无锁；配置 JSON 损坏直接 `log.Fatalf`；托盘 rebuild 泄漏 ClickedCh 监听 goroutine；前端删除隧道无二次确认。

## 跨平台复查（第三轮）

用户要求：本项目跨平台，变更必须在 macOS / Windows / Linux 三平台验证通过。

审查结论：本轮改动没有引入平台相关代码——`dock` 的 cgo 改动只在 darwin 标签内；
`atomic.Bool`、`net.Conn.SetDeadline`、`TCPConn.CloseWrite`、`WaitGroup` 三平台语义一致；
唯一的平台差异点是 `store.persist` 的 rename 覆盖语义。

实际验证：

| 目标 | 方式 | 结果 |
| --- | --- | --- |
| darwin/arm64 | `CGO_ENABLED=1 go build` + `go test -race ./...` | ✅ 编译 + 测试通过 |
| darwin/amd64 | `CGO_ENABLED=1 CC=clang go build` | ✅ 编译通过 |
| windows/amd64、windows/386 | `CGO_ENABLED=0 go build` + `go vet ./...` + `go test -c` | ✅ 编译通过（无法本机执行） |
| linux/arm64 | 容器内跑交叉编译的测试二进制 | ✅ 测试通过 |
| linux/amd64 | `CGO_ENABLED=0 go build` + `go vet` | ✅ 编译通过 |

补充修复：`store.persist` 的 rename 在 Windows 上可能被杀毒/索引服务短暂占用而 access denied，
新增 `renameFile()` 做 5 次短重试，失败时清理 `.tmp` 文件。

新增 `.github/workflows/test.yml`：ubuntu/macos/windows 三平台矩阵跑 vet + test(+race) + build，
前端单独一个 job 跑 `npm ci && npm run build`（根包 `//go:embed frontend/dist`，不先构建前端 Go 侧会失败）。
AGENTS.md 增加 3.2「跨平台验证（硬性要求）」小节与命令矩阵。
